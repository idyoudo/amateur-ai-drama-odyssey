# M10 质量门禁与自动返工（L2）

- **模块编号**：M10
- **模块职责**：把"好不好"变成**可度量、可拦截、可返工、有人负责**的机制：三层质检 + 五节点署名终审 + 镜头级自动返工。
- **上游输入**：各阶段产物（剧本、定妆、分镜、镜头素材、声音、母版）。
- **下游产出**：质检报告、门禁结论与署名记录、返工指令（回给 M5/M6/M7/M9/M11）。
- **对应页面/接口**：`/dramas/$id` 质检区、`/production` 审核台；`GET|POST /api/dramas/:id/reviews`、`PATCH /api/dramas/:id/reviews/:reviewId`。

## 1. 产品定位

**M10 是质量的裁决中枢，不是"最后一道检查"。** 它由三部分组成：

| 组成 | 作用 | 依据 |
|------|------|------|
| 三层质检 | L1 技术合规（可写死标准）→ L2 感知质量（可解释打分）→ L3 叙事与合规语义（rubric + 专家） | E-33、B-11、D-37、D-38、D-40 |
| 五节点门禁 | 剧本 → 定妆 → 分镜 → 成片 → 母版，**署名终审、不可跳过** | **D6 / EL-10** |
| 自动返工 | 只重跑失败镜头，**单镜自动重试 ≤2 次**，受预算硬约束 | D-30、E-28、E-34 |

现状问题（代码事实）：任务 `completed` **只表示供应商调用返回**，不代表画面可用（`apps/api/src/dramaWorker.ts:58-71`）；镜头表只有 `status/image_key/video_key`，无任何质量字段（`apps/api/src/dramaService.ts:14`）；陈旧任务回收也只认 `video_key` 非空（`apps/api/src/dramaService.ts:438-457`）；合成画质硬编码 1280×720 与 aac（`apps/api/src/mediaComposer.ts:72-73`）。

## 4. 目标态差距小结

1. 当前 "completed" 等价于"调用成功"，与"可交付"之间**没有任何检查**；这是最危险的质量空洞。
2. 没有门禁概念：只有单级审核，无署名、无清单、无理由码、无回溯抽检，"签字"没有成本。
3. 没有返工机制：失败只能整任务重试，无法只重跑一个镜头，也无法量化返工预算。
4. 质量数据不留存，无法做阈值标定与模型迭代。

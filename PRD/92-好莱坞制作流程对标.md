# 好莱坞制作流程对标（附录）

> 本附录登记**影视工业流程与创作方法**的依据（开发序列、结构方法、剪辑与连续性、AI 影视研究）。编号延续 [99-业界对标与调研.md](99-业界对标与调研.md) 的体系：`A` 对标产品 / `B` 标准法规 / `C` 开源 / `D` 论文指标 / `E` 工程实践 / `F` 成本基准。功能点引用时只写编号。

## 一、开发（Development）：文档序列与闸门

| 编号 | 内容 | 要点 | 出处 | 等级 |
|------|------|------|------|------|
| E-36 | **开发文档序列与权重** | 院校剧作顶点课的实际闸门顺序：Writer's Statement → Five Loglines → Story Package（Teaser Pitch + One Sheet）→ Treatment/Series Bible → Step Outline Draft I → Hook/Teaser → Step Outline Draft II → **Step Outline Rewrite（单项权重最高，30%）** → 进入 Draft | DePaul CDM FILM 397 大纲（PDF） | 行标（校方） |
| E-37 | **可量化产物规格** | Treatment（feature）≥4 页；Series Bible ≥5 页；Step Outline 场景数：feature 50–100 场 / 1 小时 pilot 25–50 场 / 半小时 12–25 场；每场含 slug line + 编号 + 一句话事件；12pt Courier New、现在时 | 同上 | 行标 |
| E-38 | **Coverage 报告结构** | 封面 → 1 句 logline → 1–3 页 synopsis → 五维评分网格（premise / structure / characterization / dialogue / production value）×（Poor–Excellent）→ comments → 结论 **Pass / Consider / Recommend**；投产前的实际闸门 | Final Draft 官方博客 | 社区/行标 |
| E-39 | **页-分钟换算** | **1 页 ≈ 1 分钟**（行业经验，非精确公式）；90 页格式化剧本通常成片 95–110 分钟；feature 甜点区 **90–115 页** | Final Draft 官方博客 | 社区/行标 |
| E-40 | **Logline 三要素** | 主角（protagonist）+ 核心冲突（central conflict）+ 结局指向 | DePaul 大纲 | 行标 |
| E-41 | **Treatment / Synopsis / Outline 分野** | treatment 5–20 页现在时叙事散文（按幕分段）；synopsis 1–3 页；outline 10–30 页编号 beat/场次表 | filmbudget.com（line producer 经验值） | 社区 |
| E-42 | **Selling script vs Shooting script** | 前者面向读者（spec，至开拍前），后者按实际拍摄收敛（production draft） | Go Into The Story（Scott Myers） | 社区 |

> ⚠️ 缺口：treatment「5–20 页/10–30 页」无工会或制片厂官方规范，只有校方下限（≥4 页 / bible ≥5 页）可核验；**不得写成"行业标准"**。table read 的标准流程与轮次亦无官方文件。

## 二、结构方法论与可校验规则

## 三、剧集形态规则（官方定义）

| 编号 | 内容 | 要点 | 出处 | 等级 |
|------|------|------|------|------|

## 四、AI 剧作与评测研究（D 系列）

| 编号 | 内容 | 结论 | 出处 | 等级 |
|------|------|------|------|------|
| D-16 | **Dramatron** | 分层/beat 驱动生成：log line → 角色 → beat → 地点 → 对白；明确承认模型缺长程语义连贯 | arXiv 2209.14958 | 论文 |
| D-17 | **Re3** | 结构化 overarching plan + 反复注入 plan 与当前故事状态 + 按连贯性重排候选，支持 ≥2000 词长故事 | arXiv 2210.06774 | 论文 |
| D-18 | **Storyteller** | SVO 三元组构建 plot node + narrative entity knowledge graph（NEKG）；人工偏好胜率 **84.33%** | arXiv 2506.02347 | 论文 |
| D-19 | **DSR（创作/格式解耦）** | 先 outline→散文，再转专业剧本格式；职业编剧盲评胜率 **75%** → 证明"一个模型同时管叙事与格式"是失败根因 | arXiv 2510.23163 | 论文 |
| D-20 | **CML-Bench 剧本评测** | 三维量化：Dialogue Coherence / Character Consistency / Plot Reasonableness | arXiv 2510.06231 | 论文 |
| D-21 | **人格保真（OOC）评测** | InCharacter：32 角色 × 14 量表访谈式测试，SOTA 80.7%；CoSER：17,966 角色 / 771 本书数据集 | arXiv 2310.17976、arXiv 2502.09082 | 论文 |
| D-22 | **DramaChain Bench（链路级）** | 覆盖 script→storyboard→keyframe→shot video→成片 全链路，5 轴 63 叶子维度；结论：**上游缺陷沿链路级联** | arXiv 2609.00646 | 论文 |
| D-23 | **多智能体短剧实践** | 层级多智能体（辩论式故事生成 + 3D 锚定首帧 + 多级 reviewer）指出 one-shot 剧本三大硬伤：叙事节奏、空间一致性、生产级质量控制 | arXiv 2605.22144 | 论文 |
| D-27 | **ObjectAlign（物体级一致性配方）** | 同时使用 **CLIP 语义相似度 + LPIPS 感知距离 + 直方图相关 + SAM 掩膜 IoU** 四项指标且**阈值可学习**，再用 SMT 检查掩膜物体嵌入、概率模型检验时序逻辑，对被标记帧块做自适应深度插帧修复（arXiv:2511.18701） | 论文 |
| D-24 | **LLM-as-Judge 不可靠（重要）** | Narrative Efficiency 与人类评分 **r=0.07**、Character Consistency **r=−0.04**（不显著）→ **自动评测不能作为唯一验收手段**；同时：最优模型逻辑矛盾率 2–5%，**17.6% 剧本含至少一处事实性违规** | DramaBench（ICLR 2026 官方虚拟页摘要） | 论文/会议 |

## 五、剪辑、连续性与 QC（E 系列）

| 编号 | 内容 | 要点 | 出处 | 等级 |
|------|------|------|------|------|
| E-53 | **ASL（平均镜头长度）基线** | 默片美国片常见 ≈5 s/镜；**1960 年代后加快，当代主流片常见 2–4 s/镜**，对白戏亦然（更多单人镜而非双人镜） | Bordwell 2007「强化连续性」 | 权威二手 |
| E-54 | **J/L cut 与 match cut** | J-cut：后场声音先入；L-cut：音视频异步；match cut / graphic match：动作、构图或形状匹配；cutting on action 保时间连续 | Wikipedia 条目 | 社区/百科 |
| E-55 | **Murch 六规则权重** | Emotion **51%**、Story **23%**、Rhythm **10%**、Eye Trace **7%**、2D Place of Screen（轴线）**5%**、3D Space of Action **4%** | Go Into The Story 引 Murch《In the Blink of an Eye》 | 权威二手 |
| E-56 | **Picture lock 与 turnover 纪律** | lock 后除例外不再改动；序列起始 **TC=01:00:00:00**、SMPTE 倒计时、音轨分层固定（对白/同期/环境/音效/音乐）、统一 **48 kHz**；TV 分段间严格 **2 s 黑场**；命名示例 `项目_季_集_LC_YYYYMMDD`；给声音的 AAF 用 **100 帧 handles** 且 consolidate 到文件夹 | FSUFILM Handbook、Dept of Post Turnover Guidelines（PDF） | 权威二手 |
| E-57 | **剧本监督的连续性字段** | 每个 take 记录：时长、主要演员位置、**屏幕运动方向**、关键动作、所用镜头、其他细节；另负责轴线与 eyeline、slating、lined script、circle takes、每日 production report | Wikipedia 剧本监督条目 | 社区/百科 |
| E-58 | **越轴是软约束（重要）** | 180° 规则条目明确「维持该规则重要性的**实证证据有限**」→ 检测应做成**告警项而非否决项**；合法越轴四法：改变运动方向、机位弧移越轴、插入缓冲镜头、pre-lap 台词 | Wikipedia 180-degree rule | 社区/百科 |
| E-59 | **自动镜头切分默认参数** | PySceneDetect：`ContentDetector` threshold **27.0**、min_scene_len **15 帧**；`AdaptiveDetector` adaptive_threshold **3.0**、min_scene_len 15、window_width 2、min_content_val 15.0 | PySceneDetect 官方文档 | 官档 |
| E-60 | **FFmpeg 可做的 QC 项** | `blackdetect`、`blackframe`（pblack 默认 32、需 ≥98% 像素低于阈值）、`freezedetect`、`silencedetect`、`astats`、`cropdetect`、`signalstats`、`ssim`、`entropy`；闪烁/banding/爆音/相位**无内置 filter，需自研** | FFmpeg Filters 官方文档 | 官档 |

## 七、平台可控性（A 系列，与 M5/M17 直接相关）

| 编号 | 平台 | 已核验事实 | 光学参数 |
|------|------|------------|----------|
| A-30 | **Kling 3.0 / Omni** | 6 种基础运镜 + 4 种 Master Shot；API：`multi_prompt`（多镜头分镜）、`shot_type`(customize/intelligent)、`elements`（角色参考）、`start_image_url`/`end_image_url`、`duration` 3–15s、`generate_audio`、`cfg_scale` | **全无**（`camera_control` 字段在 v3 已不存在，属 v1.5/1.6 时代残留） |
| A-31 | **Runway Gen-4.5 / Aleph** | API **无任何 camera 字段**，运镜只能靠提示词 + 应用内预设；官方警告**双重指挥（prompt 与设置冲突）是最常见失败模式**；输出格式支持 **ProRes / HDR10 / HLG / EXR ACEScg**（属交付能力，不等于拍摄参数可控） | **全无** |
| A-32 | **Veo 3.1** | 8s、720p/1080p/4K、原生音频、9:16/16:9、视频延长、首尾帧、≤3 张参考图 | **全无** |
| A-33 | **Seedance 1.0→2.5** | 1.0 有 `camera_fixed`(bool)；2.5 靠提示词（"光圈与焦距数字可以写，但真正起作用的是用文字描述的可见结果"） | **无**（仅布尔锁定） |
| A-34 | **Luma / Pika** | Luma `concepts[{key:"dolly_zoom"}]` 等枚举；Pika 社区文档称 zoom/pan/rotate + `-motion 0–4`（当前 API 未见，C 级） | **全无 / 部分未核验** |

> **结论（写入 M5/M17 的核心约束）**：截至 2026-10，所有主流平台"相机控制"只到**运动/构图枚举**层，**焦距/光圈/景深/快门/变形全部只能靠提示词**。因此电影摄影参数必须在**分镜层做成一致性契约**（同场戏锁定焦距档、景深意图、光位方位角、色温、帧率），并由流水线校验漂移。

## 八、为什么会"像 AI"：物理理解缺失（D 系列）

| 编号 | 内容 | 结论与用法 | 出处 | 等级 |
|------|------|------------|------|------|
| D-26 | **Physics-IQ** | 覆盖固体力学/流体/光学/热力学/磁学 5 类基准，结论：生成视频模型的物理理解 **severely limited**，且 **"visual realism does not imply physical understanding"** | Physics-IQ 项目页 / WACV 2026 论文（CVF） | 论文 |
| E-63 | **物理恐怖谷清单（可作 QC 检查项）** | 力感缺失（挥拳无转胯蹬地、落地无缓冲、坐下无挤压）、负重感缺失（持械奔跑枪身不晃）、镜头语言被架空（人物漂浮使镜头失去修辞对象）；破局路径：**高动态镜头先用物理模拟/实拍做骨架，AI 只做风格化渲染**（"顶级 AI 内容依然是重工业"） | 产业评论（传媒1号，流媒体网转载） | 社区（产业） |
| F-18 | **抽卡经济性** | 可灵 2.0 单次生成 1 分钟约 **48 元**，受抽卡成功率影响**实际可用率可能低至 5–10%**（即每条合格视频背后数十倍算力） | 同上 | 社区（产业） |

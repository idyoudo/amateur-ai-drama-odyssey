# M11 调色、母版与影视 QC（L2）

- **模块编号**：M11
- **模块职责**：把锁定剪辑变成**色彩正确、规格合规、可交付、可归档**的母版——ACES 色彩管线与调色、母版化、HDR 与多规格派生、影视 QC 清单、母版门禁、归档。
- **上游输入**：M9 锁定剪辑（Locked Cut + EDL/XML/AAF）、M8 混音 printmaster 与四类 stem、M16 品牌包（仅作渲染输入）、M4/M5 多画幅安全框约束。
- **下游产出**：Rec.709 SDR 归档母版（ProRes 422 HQ/4444 + TC 嵌入）、HDR10 独立 pass、多规格派生版本、影视 QC 报告、归档包与校验和。
- **对应页面/接口**：`/production` 母版与 QC 区、`/dramas/$id`；母版与 QC 接口待建（现仅有 `POST /api/dramas/:id/exports`，`apps/api/src/dramaProduction.ts:52-75`）。
- **边界**：**品牌包与视觉规范归 M16**；**内容审核、AI 标识与披露合规归 M18**；本模块只负责技术色彩、母版规格与影视 QC。
- **规则与依据**：D3 声音、D4 色彩/EL-08、D5 帧率/EL-09、D1 画幅/EL-01、D6 门禁/EL-10；标准编号 B-14~B-46 见 [91](91-影视技术规格与交付标准.md)，工程实践 E-53~E-60 见 [92](92-好莱坞制作流程对标.md)。

## 1. 产品定位

**母版是全片唯一的事实来源，其余一切版本都是它的派生。** 现状是「导出 mp4」：合成器把每个镜头归一化到 1280×720、libx264、AAC 128 kbps 再拼接（`apps/api/src/mediaComposer.ts:72-73`），导出记录只有一种格式（`apps/api/src/dramaService.ts:21` `format` 默认 `mp4`）——没有色彩管线、没有母版编码、没有 QC。本模块定义目标态：ACES 管线 + 固定 IDT、Rec.709 SDR 唯一归档母版、HDR10 独立 pass、影视 QC 清单，并由**母版门禁**（五门禁最后一关）阻断不合格交付。

## 3. 目标态差距小结

1. **色彩管理与母版能力为零**：全链路只有 `scale=1280:720,fps=24` 与 `libx264`（`mediaComposer.ts:72-73`），没有 IDT、没有 LUT、没有色偏统计，也没有 ProRes 母版或时间码（`dramaService.ts:21` 只有 `mp4`）。
2. **母版规格全部不合规**：音频是 AAC 128 kbps 立体声（`mediaComposer.ts:73`）而非 24-bit/48 kHz；无头尾黑场控制；无 TC 起点；无命名规则——按 B-36~B-38 逐条都不达标。
3. **字幕直接把母版堵在拒收项上**：字幕以 `subtitles` 滤镜烧录进画面（`mediaComposer.ts:103-105`），而硬字幕是平台硬规则拒收项（B-40）；同时无 5/6 s–7 s、≤2 行、23 字符、graphics safe 校验（B-32/B-33/B-16）。
4. **完全没有 QC**：没有黑帧/闪帧/坏帧/banding/响度/真峰值检测，也没有带 timecode 与缩略图的报告，更谈不上把母版做成门禁的最后一关（D6/EL-10）。
5. **HDR10 与 48fps 只是路线图文字**：EL-08 要求的独立 pass 与 B-39 的元数据、EL-11 的「保证/可选/需确认」标注均无落点。

# M16 工作区与协作（L2）

- **模块编号**：M16
- **模块职责**：为多人协作提供空间、**影视岗位角色**与权限，承载五门禁的署名审批与留痕，并定义品牌与视觉规范、外部创作工作室的治理边界。
- **上游输入**：账号、工作区配置、影视岗位任命、品牌与视觉规范。
- **下游产出**：权限判定结果、门禁署名与理由码记录、品牌套用结果、外部工作室会话。
- **对应页面/接口**：`/production`、`/studios/toonflow`、`/studios/lumenx`；`GET /api/content/workspace`、`GET|POST /api/content/brand-kits`、`GET|POST /api/studios`。
- **规则与依据**：五门禁与署名留痕的约束性要求见 [93-决策选举记录.md](93-决策选举记录.md)（D6、EL-10）；对标编号见 [99-业界对标与调研.md](99-业界对标与调研.md)。

### 1.4 外部创作工作室（M16.4）

调研结论（详见 [99-业界对标与调研.md](99-业界对标与调研.md)）：Toonflow（`HBAI-Ltd/Toonflow-app`，锁定版 Apache-2.0、master 已转 MIT，周级发布，17.1k star）与 LumenX（`alibaba/lumenx`，MIT，1.3k star，**自 2026-08-11 起无提交、无 Release，推断已停止积极维护**）。两者都做「小说→短剧」全流程，能力互补：Toonflow 强在章节事件图谱 + Agent 分层 + 画布，LumenX 强在角色三视图/参考图、批量抽卡、声音克隆、时间线精剪。

**产品定位**：外部工作室 = **可选的高级创作台**（人工精调、多模型抽卡、画风切换），**不承担主链路 SLA**；主链路（自研）承担「可复现、可批量、成本可控、可审计」的批量生产。**数据不互通是设计选择而非缺陷**，避免同一份剧本出现两个可修改的事实来源。

## 2. 目标态差距小结

1. 角色模型存在但不生效，成员无法被邀请，权限不落到操作级；**没有影视岗位概念**，因此五门禁找不到「该由谁签」。
2. `drama_reviews` 只有状态与自由文本意见，无法承载署名、理由码、AI 异议覆盖留痕与回溯抽检，EL-10 完全无从落地。
3. 品牌包「有壳无实」，未套用到成片；也缺视觉规范（画幅/安全框/色卡）这一层。
4. 外部工作室定位已定为主辅并存，但缺能力归属表以外的治理闭环；协作流程（批注、会审、dailies、决议）整体缺失，审看发生在系统之外。

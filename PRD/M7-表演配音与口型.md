# M7 表演、配音与口型（L2）

- **模块编号**：M7
- **模块职责**：把对白剧本变成「对的人、用对的音色、按表演意图说出来，并且嘴型对得上」的可用音画资产；同时产出段级/字级时间轴与配音质检结论。
- **上游输入**：M2 分集对白剧本与场景情绪、M3 角色卡（形象圣经/音色绑定）、M4 分镜（景别、镜头时长、表演意图）、M5 镜头视频与底片视频、M13 阶段任务与续跑检查点。
- **下游产出**：`voice` 音轨与段级时间轴、`narration` 独立旁白轨、口型后的镜头视频、配音/口型 QC 报告与重做记录、给 M9 的剪辑音轨与给 M12 的配音 stem。
- **对应页面/接口**：`/dramas/$id`（上传底片配音、重新生成自然对白）、`/voice-debug`；`POST /api/dramas/voice-debug`（`apps/api/src/server.ts:343`）、`POST /api/dramas/:id/episodes/:id/base-video`（`server.ts:349`）、`POST /api/dramas/:id/episodes/:id/regenerate-natural-voice`（`server.ts:395-404`）、`POST /api/dramas/:id/characters`（`server.ts:410-411`）、`POST /api/dramas/:id/episodes/:id/tracks`（`server.ts:414-415`）。

## 1. 产品定位

本模块是「表演」这一层的兑现处。影视工业把「表演」当创作对象（表演指导、ADR、口型），RTO 现状只有一段按说话人拼起来的 TTS。边界如下：

- **属于本模块**：表演设计（基调/情绪曲线/镜头级表演指令）、对白解析与说话人归属、音色库与角色配音绑定、情绪与演绎控制、口型同步、配音质检与重做、底片配音与调试路径。
- **不属于本模块**：字幕文本、时间轴交付格式与本地化（M12.2）、多轨混音、响度与 stem 交付（M8）、角色形象资产与定妆（M3）、任务排队与重试预算（M13）、质量总门禁（M10）。

四条原则：

1. **先有表演意图，再有声音**：表演基调与镜头级指令是一等输入，而不是让 TTS 自由发挥。
2. **音色是角色的全局属性**：`角色 ↔ 音色` 全剧一次绑定、带版本与指纹；**禁止按出场序隐式分配**（依据：E-32）。
3. **旁白是独立音轨，不是丢弃物**：旁白要有独立音色与独立轨道，而不是静默（实现于 `apps/api/src/dialogueScript.ts:21-24`，丢弃点见 `apps/api/src/dramaWorker.ts:378-381`）。
4. **口型是可选增强**：只做近景正脸、有质量门、有回退路径；宁可降级也不产出恐怖谷画面（依据：NFR-07、D-36）。

## 4. 目标态差距小结

1. **口型全缺**：阶段枚举、人脸质量门、引擎抽象、切片对齐、B-26 同步验收与回退路径都没有，这是「出戏」的最大来源。
2. **音色不可选且隐式分配**：现状按出场序轮转两个硬编码音色（`dialogueScript.ts:60-63`），与 E-32 直接冲突；无试听、无版本、无指纹。
3. **旁白被丢**：旁白文本在解析层被丢弃（`dialogueScript.ts:21-24`），成片既没声音也没字幕。
4. **无表演层**：没有基调/情绪曲线/镜头级表演指令，情绪与语速控制基本靠静默忽略（`voiceProvider.ts:53-74`）。
5. **无配音质检**：没有跨集音色回归、没有角色电平一致性、没有可懂度检测，只能人工整集试听。
6. **时间轴口径矛盾**：同一产物同时被标 `estimated` 与 `provider-segments`；本模块裁决为「如实标记来源 + ASR 复核」，落点 M12.2-F01。

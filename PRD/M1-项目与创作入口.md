# M1 项目与创作入口（L2）

- **模块编号**：M1（对应 L1 模块地图 M1「立项、包型、预算、画幅与交付目标」）
- **模块职责**：把「一部长篇小说」或「一组图片」变成一个**影视立项**：包型、画幅与交付目标、三级预算、五门禁责任明确，可被长形式流水线执行，并管理项目全生命周期。
- **上游输入**：小说/文字/图片、logline 与目标平台、包型与画幅交付目标、门禁责任人与预算。
- **下游产出**：立项记录（含交付规格与预算结构）+ 首批任务（开发文档序列、图片源分镜）。
- **约束决议**：D1（画幅）、D2（结构/时长）、D4（色彩）、D5（帧率）、D6（门禁）见 [93-决策选举记录.md](93-决策选举记录.md)；派生 EL-01/EL-02/EL-03/EL-10/EL-11。
- **对应页面/接口**：`/dramas`、`/dramas/new`；`POST /api/dramas`、`POST /api/dramas/upload`、`POST /api/dramas/from-images`、`POST /api/dramas/batch`、`GET /api/dramas/models`。

## 2. 目标态差距小结

1. 缺「影视立项」这一步：只有项目名与正文，没有 logline、目标平台、分级预估与包型，导致后续门禁与预算无锚点。
2. 单集时长上限 600 秒与剧集式形态（22–45 分钟/集）直接冲突，是本模块最硬的改造点。
3. 画幅只有单值概念，没有三画幅交付目标与安全框冻结，9:16 衍生版会退化为裁切塌陷。
4. 项目层没有先导集与 pod 放行机制，长形式失败半径无法收敛。
5. 五门禁责任人与三级预算未在立项时绑定，质量与成本都变成事后统计。

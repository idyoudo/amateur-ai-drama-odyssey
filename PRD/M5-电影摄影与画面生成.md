# M5 电影摄影与画面生成（L2）

- **模块编号**：M5
- **模块职责**：把 M4 的镜头清单变成**有镜头语言、有光学意图、有布光设计、物理可信**的关键帧与镜头片段——即用 AI 生成通道执行一次"虚拟拍摄"。
- **上游输入**：M4 的分镜表（景别/角度/运镜/焦距档/景深意图/光位/色温/衔接关系）、M3 的角色锚点图集与形象圣经、M6 的身份锁前缀与参考图挂载、M14 的预算与配额。
- **下游产出**：镜头关键帧、镜头视频片段（含候选与选择位）、每镜摄影参数快照与质检结论，登记 M15 资产库，送 M6 一致性判定、M9 剪辑、M11 调色母版。
- **对应页面/接口**：`/dramas/$id` 分镜区（`apps/web/src/pages/Dramas.tsx:283-296` 现仅列出编号/状态/时长/prompt 与下载链接）；`POST /api/dramas/:id/generate-video`、`POST /api/dramas/:id/episodes/:eid/generate-video`、`GET /api/dramas/:id/shots/:sid/(image|video)/(stream|download)`。
- **与 M6 分工**：M5 负责"拍得像电影"并产出候选与重做能力；M6 负责"是不是同一个人/同一场戏"，并给出该不该重做。二者共用抽帧与质检管线，不重复登记同一功能点。

## 1. 核心约束（决定本模块全部设计）

**平台可控性上限（依据：A-30~A-34）**：截至 2026-10，所有主流视频平台的"相机控制"只到**运动/构图枚举**层——Kling 3.0 的 `camera_control` 字段已移除（A-30），Runway Gen-4.5/Aleph API **无任何 camera 字段**（A-31），Veo 3.1 无光学参数（A-32），Seedance 2.5 仅靠提示词（A-33），Luma/Pika 只有零散枚举（A-34）。因此：

> **M5 明确声明：RTO 无法获得焦距、光圈、景深、快门角等真实相机参数。摄影控制只能通过「提示词契约 + 分镜层锁定 + 生成后漂移检测」三件事实现**，任何"设置里改焦距档"的交互都必须落到提示词与校验上，不得假装平台支持（依据：A-30~A-34；反例警示：Runway 官方指出 prompt 与设置双重指挥是最常见失败模式，A-31）。

## 目标态差距小结

1. **结构性差距**：全链路没有摄影参数概念——`drama_shots` 只有 `prompt/duration_sec/status`（`apps/api/src/dramaService.ts:14`），出图固定 `1280*720`（`apps/api/src/tokenPlanMedia.ts:67`），合成固定 1280×720/24fps（`apps/api/src/mediaComposer.ts:72`）。焦距、景深、布光、色温全部无处登记，也无法校验漂移。
2. **平台现实**：即便登记了参数，平台也只认提示词与运动枚举（A-30~A-34）→ 本模块的成败取决于**契约化提示词 + 分镜层锁定 + 生成后检测**，而不是参数面板。
3. **物理可信度为零**：无物理骨架通道、无物理恐怖谷检查项，动作戏与负重戏必然出现"人物漂浮"（D-26、E-63）。
4. **成本结构未治理**：无 Draft 两阶段、无分级路由、无 k 值观测，抽卡成功率可能低至 5–10%（F-18），单位成本不可控。
5. **择优缺失**：每镜单次出图，没有候选池与选择位，质量靠运气（旧文 `M5.1-F03` 已登记该缺口，本版继承并纳入 M5.4-F03）。

# M4 分镜、previz 与导演台（L2）

- **模块编号**：M4
- **模块职责**：把剧本变成**开拍前已锁定的镜头清单与预演**——分镜脚本（shot list）、镜头语言契约、覆盖与调度、animatic 与 previz、轴线与视线校验、分镜编辑与**分镜门禁**、安全区与多画幅裁切预演。
- **上游输入**：M2 输出的分集剧本与 Step Outline、M3 角色卡与定妆确认、M1 包型与画幅目标（2.39:1 主母版 / 16:9 / 9:16）、M17 供应商光学参数能力矩阵。
- **下游产出**：`drama_shots` 结构化镜头清单、每镜镜头语言契约（景别/角度/主运镜/焦距档/景深意图/光位与色温）、覆盖与调度方案、animatic 与 previz 产物、越轴与视线告警清单、安全区校验结果、分镜门禁签署记录、变更影响分析报告。
- **对应页面/接口**：`/dramas/$id` 分镜区；`POST /api/dramas/:id/generate-video`（`apps/api/src/server.ts:382`）、`POST /api/dramas/:id/episodes/:eid/generate-video`（`apps/api/src/server.ts:389`）。

## 1. 产品定位

本模块是「前期」的收口环节：**镜头语言必须在开拍前确定，而不是在生成时靠提示词碰运气**。依据 A-30~A-34，截至 2026-10 所有主流视频平台（Kling 3.0 的 `camera_control` 字段在 v3 已不存在、Runway Gen-4.5 API 无任何 camera 字段、Veo 3.1 与 Seedance 2.5 同样只有枚举/提示词层、Luma 仅有 `concepts` 枚举）的相机控制只到运动与构图枚举层，**焦距、光圈、景深、快门、变形全部只能靠提示词**。因此光学与光线意图必须在 M4 做成**逐镜一致性契约**，由流水线校验漂移（同样的结论写入 M5/M17）。

两条与"像 AI"直接对抗的约束：

1. **物理骨架优先**（E-63、D-26）：生成模型的物理理解 severely limited，且「视觉真实不等于物理正确」。高动态、负重、碰撞镜头**先走物理模拟或实拍骨架**，AI 只做风格化渲染。
2. **越轴是告警而非否决**（E-58、B-46）：180° 规则的实证证据有限，检测只作告警输出与人工确认，不得自动判某镜不合格。

## 目标态差距小结

1. **分镜只有 prompt + 时长**：表结构仅九列（`apps/api/src/dramaService.ts:14`），没有景别、角度、运镜、焦距、景深、光位、色温、情绪、道具、转场等镜头语言字段，镜头不可控也不可复现。
2. **固定 6 镜与长形式冲突**：镜头数写死为 6 并由校验强制（`apps/api/src/dramaLogic.ts:17`、`apps/api/src/dramaLogic.ts:40-42`），无法支撑 22–30 分钟/集（D2）的节奏设计。
3. **没有 previz 与物理通路**：既无可播放 animatic，也没有多画幅裁切预演与安全区校验，更没有高动态镜头的物理骨架通道；EL-02 在分镜阶段完全没有落点。
4. **没有方向连续性能力**：无轴线、视线、屏幕运动方向字段，越轴与视线不一致无法检测（也就无法做到「告警而非否决」）。
5. **分镜不可编辑、不可锁定、无门禁**：写入即整集替换且已有分镜直接报错（`apps/api/src/dramaService.ts:393-394`），没有锁定、会审、变更影响分析，D6/EL-10 的分镜门禁尚未落地。
6. **生成触发粒度太粗**：只有整剧/整集触发（`apps/api/src/server.ts:382-394`），与 EL-04「返工粒度到镜头区间」不一致。

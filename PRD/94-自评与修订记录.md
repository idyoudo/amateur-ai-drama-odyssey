# 自评与修订记录（附录）

## 五、第 4 轮自评（依据编号统一）

**发现**：附录编号存在**同号异义**（19 处）——`A-01~A-10` 在 99 第四章（市场平台能力）与第五章（角色一致性）重复占用；`D-01~D-05`、`D-10~D-12` 同样跨章重复；`B-21` 在 91 是 EBU R128 响度、在 92 是 Emmy 形态规则。这会让"依据可追溯"失效。

**修复**：
1. 99 第四章的平台能力条目统一改为 **A-70~A-84**；第五章一致性条目保留 `A-01~A-12`；
2. 99 第五/六/七章的检测与评测条目改为 **D-30~D-40**；叙事与留存条目保留 `D-01~D-12`（D-16~D-27 在 92；原 D-13~D-15 已重编号为 D-38~D-40）；
3. 92 的 Emmy 形态规则由 `B-21` 改为 **B-89**；
4. 按上下文把 60+ 处模块引用改到正确编号（如 M8/M11 的 B-21 仍指响度、M2/M9 的 B-89 指剧集形态、M6/M10 的 D-30 指人脸阈值、M7 的 D-35/D-36 指口型门与实测）。

**结果**：附录条目 **270** 条，模块悬空引用 **0**，同号异义 **0**；19 模块 / **631 功能点**，状态取值 100% 合法，`已实现` 证据完整率 100%。

## 六、第 5 轮自评（Demo 实测 + 对抗复核）

**方法**：把 Demo 产物当作被审对象，由选举评估员与独立复测脚本双向挑错（评估员可访问 `demo/` 与 PRD）。

**评审员用实测挑出的缺陷与修复**

| 编号 | 缺陷（实测） | 修复 |
|------|--------------|------|
| CR-16 | 动画分镜文件在构建中途为 0 字节，但 QC 此前仍判通过（未校验文件存在与非空） | 复测改为 **fail-closed**：产物缺失/为空即 QC FAIL，且复测在交付单写出之后执行 |
| CR-17 | 仪表盘引用了 `review_169_s04.png`、`review_916_s08.png`，而生成器只产出 s01/s03/s07（断链） | 仪表盘媒体列表改为**按磁盘实有文件动态生成** |
| CR-18 | QC 声称「384 帧 @24fps」，但 WebP 逐帧时基为 42 ms → 实际约 23.81 fps（时间基量化误差未披露） | 不再声称 WebP 是 24fps 母版：母版时间线以 **`out/timeline.json`（1/24 s 精确）** 为准，WebP 标为**代理样片**并实测其漂移（阈值 ≤1%），QC 如实报告 |
| CR-19 | 交付单与元数据声称 24-bit/48 kHz，实际写的是 16-bit WAV | WAV 写入器改为 **24-bit 立体声**，复测从文件头读取位深/声道/采样率并断言 |
| CR-20 | 「色卡 ΔE = 0.0」是自证（用同一渲染结果对比自身），无检验价值 | ΔE 改为**从有损编码后的 WebP 取样（区域中位数）**对比声明参考；第一次实测即暴露真实偏差（最大 ΔE 7.0），据此放大色卡并提升编码质量后复测通过 |
| CR-21 | 缺独立复测、缺代理声明、缺头尾黑场检查 | 新增 `demo/verify.py`（只读磁盘产物重新测量）、元数据 **PROXY** 声明（EL-16）、头尾黑场（B-37）与安全区几何（B-16）检查 |

**新增交付物**

- `demo/verify.py`：独立复测（fail-closed），只在产物齐备后判定，退出码 0 = 全项通过
- `demo/report.py`：由实测 JSON **生成** `demo/README.md` 与 `PRD/97-Demo验证报告.md`，避免手抄数字漂移
- `demo/build_demo.py`：程序化生成三画幅代理分镜、四层声音与合规母版、字幕、交付单、元数据、时间线、仪表盘

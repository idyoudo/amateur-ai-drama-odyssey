# M2 剧作开发与剧本（L2）

- **模块编号**：M2
- **模块职责**：把长篇小说变成**可开拍的剧作资产链**——立项 logline 与 story package、长篇解析与章节事件图谱、Treatment 与 Series Bible、Step Outline 与结构校验、剧本生成与多稿改写、剧本质量评测与开拍门禁、材料溯源与合规。
- **上游输入**：M1 立项（包型 6 集×22–30 分钟、画幅与交付目标、预算）、原文全文、题材与受众标签、M18 权利链与授权状态。
- **下游产出**：logline 与 one sheet、章节事件图谱与实体/情节状态图、Treatment、Series Bible、Step Outline、分集剧本与 revision 稿、coverage 报告与剧本门禁签署记录、材料 provenance 台账。
- **对应页面/接口**：`/dramas/$id` 剧本与分集编辑区；`GET/POST /api/dramas/:id/episodes/:episodeId/versions`（`apps/api/src/server.ts:407-409`）、`POST /api/dramas/:id/characters`（`apps/api/src/server.ts:410`）、`POST /api/dramas/:id/episodes/:episodeId/regenerate-natural-voice`（`apps/api/src/server.ts:395`）。

## 1. 产品定位

本模块是「小说 → 成片」链路上的**第一道质量闸门，也是链条上最严的一道门禁**。依据 D-22，剧本阶段的缺陷会沿 script → storyboard → keyframe → shot video → 成片整条链路级联放大；上游一个场次的功能缺失，到成片阶段只能靠重生成买单。因此：**剧本门禁最严、返工最便宜、拒绝成本最低**。

三条不可让渡的原则：

1. **Rewrite 是一等公民**（E-49）：Step Outline 必须两稿 + Rewrite，且 Rewrite 是开发序列中**单项权重最高（30%）**的环节；「改写」在本模块是与「生成」平级的产物类型，不是补救手段。
2. **创作与格式解耦**（D-19）：先 outline→散文，再转专业剧本格式；要求一个模型同时管叙事与格式正是失败的根因（职业编剧盲评胜率 75% 的对照组）。
3. **自动分只做预筛，上线判定需人类盲评**（D-24）：LLM-as-Judge 与人类评分相关性 r=0.07 / r=−0.04，**不得作为唯一验收手段**；自动评测输出「预筛结论」，门禁结论必须由人类盲评 + 署名产生（D6/EL-10）。

**M2 不做**：角色定妆与音色克隆（M3）、镜头语言与画面提示词（M4/M5）、敏感内容最终裁决与披露（M11/M18）、平台排期（M12）。

## 目标态差距小结

1. **没有开发序列**：现状从原文直接跳到分集大纲与剧本（`apps/api/src/bailian.ts:357-391`），logline、story package、one sheet、Treatment、Series Bible、Step Outline 六类产物全部缺失，结构无从校验。
2. **长篇解析只有摘要没有图谱**：叶块摘要（120–220 字）与金字塔归约是唯一上下文来源，没有章节事件图谱、实体图谱与情节状态图，长程连贯完全依赖压缩摘要。
3. **结构规则零覆盖**：现状只校验集数与 synopsis 非空（`apps/api/src/bailian.ts:376-379`），三幕节拍、15 拍、Truby 四节点、Harmon 8 步、A/B/C 线、形态规则（B-89/E-50）全部未实现。
4. **改写不是一等公民**：只有整集重生成与递增版本号（`apps/api/src/dramaService.ts:142-151`），没有两稿 + Rewrite、没有 notes 消费闭环、没有去名盲测与 exposition 检测。
5. **质量评测与闸门缺失**：无任何自动评测，也没有人类盲评与署名的剧本门禁材料（`apps/api/src/dramaService.ts:20` 的 reviews 只到分集粒度）。
6. **溯源与合规空白**：AI 生成材料无 provenance 标注，无人类 first writer 署名，AI 衍生文本与 source material 不加区分。

# M3 选角、角色资产与数字替身（L2）

- **模块编号**：M3
- **模块职责**：完成**选角与定妆**，并把角色固化为可复用、可校验、**权利清晰**的资产——影像锚点、形象圣经、音色与数字替身授权。
- **上游输入**：M2 剧本中的角色清单与人物小传、导演/制片的形象意图。
- **下游产出**：定妆确认结论、形象圣经（look bible）、锚点图集与身份嵌入，供 M4/M5/M6/M7 使用。
- **对应页面/接口**：`/dramas/$id` 角色区（待建）；现有接口 `POST /api/dramas/:id/characters`、`GET /api/dramas/:id/assets`。

## 1. 产品定位

**定妆是五门禁之一**（剧本 → **定妆** → 分镜 → 成片 → 母版，依据：D6/EL-10），因为它是后续所有画面的**唯一视觉事实来源**。基准错了，后面每一镜都会错，且返工成本按镜头数线性放大。

三个不可退让的原则：
1. **形象圣经优先**：角色外观、服装、色彩、光线规范一经确认即成为契约，任何偏离都视为缺陷；
2. **身份锚点可校验**：定妆产出可计算的身份嵌入（人脸/主体特征），供 M6 做跨镜一致性判定；
3. **权利先于生成**：凡涉及真人形象、声音或数字替身，**授权记录先于生成**（依据：M18 合规要求、WGA/SAG 边界）。

现状（代码事实）：角色只有数据库字段 `name/profile/reference_key/voice_key/status`（`apps/api/src/dramaService.ts:17`），维护接口存在（`apps/api/src/server.ts:410-411`），但**前端无任何角色界面**，音色由系统按出场序隐式分配（`apps/api/src/dialogueScript.ts:5,60-63`；`apps/api/src/dramaWorker.ts:375-377`），场景表仅建表无读写（`apps/api/src/dramaService.ts:18`）。

## 4. 目标态差距小结

1. 角色目前**只有字段没有形象**：无三视图、无锚点、无嵌入，一致性从源头无从保证。
2. **没有定妆门禁**：五门禁中的第二个节点事实上不存在，形象未经确认就进入生产。
3. **没有形象圣经**：跨集一致性没有契约可依，返工只能靠人盯。
4. **权利链空白**：数字替身、肖像、声音复刻全无登记与阻断机制，商用与发行存在法律风险。
5. 场景与道具表建了不用，服装/状态连续性无处落地。

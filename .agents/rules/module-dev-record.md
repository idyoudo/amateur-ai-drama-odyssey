# 强规则三：开发任务必登记模块文档（每模块一个总入口）

权威正文。Cursor 端 `.cursor/rules/module-dev-record.mdc`（alwaysApply）与本文同义；`AGENTS.md`（跨 harness 唯一入口）与 `GOVERNANCE.md`（强规则三）引用本文。改规则时先改本文，再同步 `.mdc`、`AGENTS.md`、`GOVERNANCE.md` 三处。

## 总入口

每个 PRD 模块（M1–M19）在 `docs/modules/M#-<中文名>.md` 维护一份**模块开发总入口**（模块级文档），文件名与 `PRD/M#-<中文名>.md` **同名一一对应**。`docs/modules/README.md` 是模块文档总索引。

三方一致（机器校验，`tools/prd_guard.py`）：PRD 模块文件 ↔ `docs/modules/` 模块文档 ↔ `docs/modules/README.md` 索引，**集合必须完全一致**；多一个、少一个、改名，提交即被拒。

每个模块文档固定四节：`更新日期` + `§1 现行状态速览` + `§2 任务登记` + `§3 专题文档索引` + `§4 变更记录`。

## 适用范围

「开发任务」指任何触及 `M#` 模块职责的实现、改动、排查、文档、迁移——不只是 PRD 变更，也包括写 `film/`、`apps/` 代码、改 `docs/designs`/`docs/plans`、跑迁移等。拿不准是否属于某模块时，按属于处理并登记到最相关的模块文档。

## 必须

1. **开发前必读总入口**。动手前（含快路径修复、排查、文档、迁移）Read 目标模块总入口的 §1 现行状态速览、§2 任务登记（找相关任务与「待开发/阻塞」项）、§4 最近变更记录；再按 §3 索引只读与本任务相关的专题文档。未读不得改代码或下结论。
2. **开工即登记**。在 §2 任务登记新增一行（编号 `M#-TNN`，模块内递增）或把已有行改为「进行中」：编号、任务、状态、日期、主文档/计划、说明。
3. **完成即回写**。任务完成或口径变化时：更新 §2 该行状态；在 §4 变更记录最上方加 `### YYYY-MM-DD <主题>`，3–10 行写规则、口径、入口与实现位置，不写过程；新增的专题文档、计划、执行规格登记到 §3 或该任务行；更新文首「更新日期」。
4. **回顾以总入口为准**。回答「之前怎么做的 / 现在什么口径 / 还有什么没做」时，从总入口出发，引用 `M#-TNN` 与章节；专题文档与总入口冲突时以日期新者为准，并把另一处改正。
5. **废弃先登记后删除**。专题文档整体失效时，先在 §3 写明原因与替代，再删除文件并修正指向它的链接；`docs/plans`、`docs/spec` 是历史记录，不删除。

## 与强规则一的关系

任务完成若把 PRD 功能点状态流转为「已实现」，须**同时**按强规则一登记 PRD 三处台账（`--new-entry --type 状态流转`）。模块文档登记是开发侧台账，PRD 台账是需求侧台账，两者不互相替代。

## 禁止

- 跳过总入口，直接按记忆、旧专题文档或 `docs/plans` 开发或回答。
- 完成模块任务后不更新 §2 / §4 就结束本轮。
- 在专题文档里另起一份任务清单替代 §2。
- 只写代码 / 只改 `docs/designs`，不在对应模块文档登记。

## 例外

仅当用户在本轮明确说「不登记」时可跳过第 2、3 条，并在回复里注明未登记。第 1 条（开发前必读）不可跳过。

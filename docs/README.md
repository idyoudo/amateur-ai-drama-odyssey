# docs/ 文档地图与归位约定（权威）

> 本文件是 `docs/` 目录的**唯一索引与归位约定**。任何人在 `docs/` 下新增、删除、移动 `.md` 文件，**必须同步更新本文件**，
> 否则 `python3 tools/prd_guard.py --all` 会报「索引不一致」。归位原则见 [PRD/README.md](../PRD/README.md) 第六节（本约定是其细化）。

## 一、目录约定（内容性质决定位置，不按作者/时间）

| 目录 | 放什么 | 不放什么 |
|------|--------|----------|
| `docs/architecture.md` | **系统架构**（唯一）：技术选型、进程拓扑、19 模块→代码包映射、宿主基线边界、非目标 | 具体模块的实现细节（进 designs/） |
| `docs/designs/` | **技术设计**：数据模型、API 契约、任务编排、存储血缘、权限、测试策略等「怎么实现的细节设计」 | 计划、工单、选举票型（进 plans/） |
| `docs/plans/` | **计划与决策**：实施计划、工单拆分、切片方案、选举记录、待裁决清单 | 技术设计文档（进 designs/） |
| `docs/modules/` | **模块级开发总入口**（M1–M19 每模块一份）：现行状态速览 + 任务登记 + 专题文档索引 + 变更记录（强规则三） | 需求（进 PRD/）、技术设计（进 designs/） |
| `docs/spec/` | **执行记录与验证证据**：由脚本生成的验证报告（禁止手抄数字） | 方案、计划 |
| `docs/guid/` | **部署、运维、使用指南** | 需求、设计 |
| `docs/agent-prd-method.md` | **工作方法**（八步工作流，跨项目可复用的方法论） | — |

## 二、命名约定

- 文件名用中文描述内容（与 PRD 模块文件一致），不编号（编号会随增删漂移）。
- `P1-` 前缀表示 P1 阶段的计划/决策；切片方案用 `P1-<切片>-<主题>`。
- 验证证据文件名形如 `<切片>-验证记录.md`，且必须**由脚本生成**。

## 三、强制规则（门禁校验）

1. **断链 = 违规**：仓库内任何 `.md` 的相对链接目标必须存在（`prd_guard.py --all` 全量扫描）。
2. **索引一致 = 强制**：`docs/` 下每个 `.md`（除 `README.md` 自身与 `docs/modules/`，见第 4 条）都必须在下方「文档清单」登记，且清单里的文件必须真实存在——多一个、少一个都报错。
3. **验证证据禁手抄**：`docs/spec/` 下的文件必须由脚本生成，数字与产物一致。
4. **`docs/modules/` 自索引**：该目录每个 `.md` 由 `docs/modules/README.md` 索引（不逐条登记进下方「文档清单」），并由 `prd_guard.py` 校验其与 `PRD/M*.md` **三方一致**。

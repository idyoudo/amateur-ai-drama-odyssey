# 模型多提供商设计

> 目标：同一模型类型（kind）可配置多个提供商，任意时刻只有一个 `active` 生效；切换后新任务使用新提供商，其余配置保留。

## 数据模型

`model_providers`：

| 字段 | 说明 |
|------|------|
| id | 主键 |
| kind | `text` / `image` / `video` / `tts` / `music` / `lipsync` |
| name | 提供商名称，同 kind 下唯一（便于切换时辨认） |
| model | 模型名 |
| api_url | OpenAI 兼容或厂商端点 |
| api_key | 明文存库，API 永不回传 |
| active | 是否生效；同 kind 最多一个 true |
| created_at / updated_at | 审计时间 |

`model_configs`（旧版单配置表）保留但不再写入；首次启动时若 `model_providers` 为空，会把旧表每条记录迁移为名为「默认配置」的生效提供商。

## 运行时

- `_load_model_config()`：先读环境变量，再用每个 kind 的生效提供商覆盖；没有生效提供商时保留 env 兜底。
- 适配器仍接收 `{model, api_key, api_url}`，无需改动。
- 任一写操作后刷新进程内缓存 `_model_config`。
- worker 每次轮询重新读取生效提供商，切换后无需重启 worker。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/models/config` | 每类含 `config`（生效值）、`providers`（全部）、`available` |
| POST | `/api/models/providers` | 新增；同类首个自动生效 |
| PUT | `/api/models/providers/{id}` | 编辑；空 Key 保留、掩码哨兵忽略、可显式清除 |
| POST | `/api/models/providers/{id}/activate` | 切换生效；同类其余自动停用 |
| DELETE | `/api/models/providers/{id}` | 删除；若为生效项，自动接续同类最近一个 |
| PUT | `/api/models/config` | 旧版兼容：更新/创建每个 kind 的生效提供商 |

约束：

- 同 kind 下名称唯一，重复返回 409。
- `kind` 非法、URL 非 http(s)、字段超长返回 422。
- 仅管理员可写；其他角色只读。

## 页面

- 入口：SPA 侧边栏「系统 → 模型」（`#/models`）；旧地址 `/models` 307 跳转到 SPA。
- 每个 kind 一张卡：生效状态、提供商列表（名称/模型/端点/Key 末四位）、「设为生效 / 编辑 / 删除」。
- 卡片底部内联「添加提供商」：名称、厂商预设、模型、URL、Key。
- 非管理员不显示任何编辑控件。
- 保持整页分区与留白，不使用向导。

## 非目标

- 不做按镜头自动路由到不同提供商（项目级路由仍只覆盖 model/api_url）。
- 不做 Key 的加密存储或外部密钥管理（当前为数据库明文，API 脱敏）。
- 不做提供商健康检查与自动故障切换；切换由人决定。

# AADO 任务编排设计（docs/plans/任务编排设计.md · M13）

> 落地 `PRD/M13-任务编排与可靠性.md`。借鉴：RTO `dramaService.ts`（PG 队列）+ audit `parse-compare-schedule.ts`（intent log）。
> 技术栈：PostgreSQL 自建队列（无 Redis/BullMQ），Python worker（`psycopg`/`asyncpg`）。

## 一、任务状态机（类型化 PG enum，禁止字符串码混搭）

```text
queued → running → completed
   │         │
   └─ cancelled    ├─ failed(可重试) ──重试──→ queued
                   ├─ failed(重试耗尽) → retry_exhausted
                   └─ unknown(结果不确定) → 对账队列 → resolved/requeued
```
状态流转强校验在 claim 层；`advance_stage` 幂等推进阶段 DAG（借鉴 RTO `advanceDramaProject`）。

## 二、领任务与租约（借鉴 RTO `dramaService.ts:547-620`）

```sql
-- 先回收僵尸，再领下一个
UPDATE jobs SET status='running', locked_until=NOW()+INTERVAL '90 min',
                lease_epoch=lease_epoch+1, attempts=attempts+1
WHERE id = (SELECT id FROM jobs
            WHERE status='queued' AND available_at <= NOW()
            ORDER BY priority DESC, created_at
            FOR UPDATE SKIP LOCKED LIMIT 1)
RETURNING *;
```
- 心跳每 20s 续租 `locked_until`（只对 `lease_epoch` 匹配的行）。
- 每次落库/调供应商前 `assert_lease` 校验 epoch（fencing）。

## 三、幂等与指纹（NFR-01 重复付费 = 0）

1. `jobs(idempotency_key)` 唯一索引 + `ON CONFLICT DO NOTHING` 幂等入队。
2. `idempotency_key = f"{project}:{episode}:{shot}:{type}:{input_fingerprint}"`，
   `input_fingerprint = sha256(prompt + model_version + params + seed + 参考素材 hash)`。
3. **模型升级必须换指纹**，否则新旧产物混用。
4. 提交前查重：命中历史产物 → 复用 + 记节省金额（M14.4）。

## 四、checkpoint 与断点续跑（NFR-02 ≥99%）

- `jobs.checkpoint JSONB` 记录已完成对象键 + 指纹 + lease_epoch。
- 长文本（M2）沿用 RTO 输入指纹续跑：`sourceFingerprint` 判定「续跑 vs 作废」。
- 中断恢复：读 checkpoint，已完成镜头调用次数 = 0。

## 五、intent log（结果不确定对账，M13.4-F05，借鉴 audit）

```text
出站供应商调用前：
  1. 落 intent(payload_frozen, fingerprint, client_op_id, request_id, status='intended')
  2. 发送，成功 → status='submitted'；超时/异常 → status='unknown'
  3. unknown 任务进对账队列，用 request_id 查单；已有 task_id 绝不重投
  4. 对账结论 resolved/requeued，保守计入成本
```

## 六、僵尸回收与对账兜底（借鉴 RTO `dramaService.ts:438-502`）

- `reclaim_stale`：`status='running'` 且 `locked_until < NOW()` → 检查「durable 输出已存在」：
  存在 → 翻 `completed`（不重复付费）；不存在 → requeue 一次，超限 `retry_exhausted`。
- 回收前用 checkpoint 校验实际进度，禁止盲目重发。

## 七、重试与失败分类（M13.7）

| 错误类 | 处置 |
|---|---|
| 网络/超时/5xx | 指数退避重试（封顶 60min），受全局重试预算约束 |
| 内容类（质量不合格/审核拒绝） | **不自动重试**，改参数或转人工 |
| 4xx（参数/鉴权） | 终止 + 归因 |
| 预算超限 | 阻断 + 转人工（M14 联动） |
| 供应商熔断 | 切备用模型/降档 + 通知 |

- 单镜自动重试硬上限 **K≤2**（`PRD/M5.6-F04`、M6.6-F01）。
- 全局重试预算：`重试数/总请求数` 上限，超限拒绝重试转人工。

## 八、可观测性（M13.8）

- 结构化日志 + `request_id`/`job_id` 贯穿 + 敏感字段脱敏（借鉴 audit pino redact）。
- 每次付费调用记录：指纹/供应商/耗时/用量/结果/错误/lease_epoch，可 5 分钟定位。
- **补齐 audit 的缺口**：加 metrics（失败率/队列积压/成本/门禁 SLA）+ 告警通道（超限 5 分钟通知）。

# P1-A 切片范围 · 决策选举记录

> 规则沿用项目既有机制（`PRD/93-决策选举记录.md` 定义）：**结构化选项 + N 名背对背独立评估员 + 多数决**，
> 每位评估员必须给出「胜出理由 / 最大风险 / 强制缓解措施 / 落选方案核心诉求的低成本覆盖」。
> 本记录不是 PRD 文件（归 `docs/plans/`），不受 GOVERNANCE 强规则一台账约束；但结论对**实现**具约束力。

## 一、议题与选项

**议题**：要让 P1 电影化主干真正动起来、且在**无 ffmpeg / 无 GPU / 无付费凭据**条件下**可机器验证**，
本轮应当先实现哪一个能力簇作为最小主干切片（vertical slice）？

| 选项 | 内容 | 机器可验证性（题干自评） |
|------|------|--------------------------|
| **A** | 镜头契约与安全框预检闭环（M4/M5 为主干，联动 M6/M10） | 最高（纯函数 + 纯几何） |
| B | 母版 QC 与声音合规闭环（M8/M11 为切片） | 高（但 Demo 已覆盖约 12 项，增量偏小） |
| C | 门禁与预算治理闭环（M10/M14 为切片） | 高（但无付费调用时无治理对象） |
| D | 窄切片组合（跨模块薄切） | 中（链路长、单点浅） |

## 二、计票

- 评估员：**5 名**，背对背独立（互不可见），各自实读 PRD 与 `demo/` 源码后投票；
- 票型：**A = 4 票，B = 1 票**（C/D 各 0 票）；
- 结果：**A 胜出**（过半数，无需进入平票决选）；
- 5 名评估员给 A 的四种审查角度各不相同（可机器验证性 / P1 退出标准覆盖度 / 增量与复用 / 风险与失败半径 / 下游可衔接性）。

## 三、胜方核心理由（按评估员，逐条可复核）

1. **可机器验证性最强**：`M5.1-F01` 的验收原文是「同分镜重复生成提示词**字节级一致**」（`PRD/M5-电影摄影与画面生成.md:22`），
   天然可用 sha256 对拍；`M5.1-F02`「多主运动镜头数 = 0」、`M5.3-F02`「fill ≤ key 50%，违规镜次提交数 = 0」
   （`PRD/M5:44`）均为数值比较，不需要听/看/人耳人眼。
2. **唯一被 PRD 明文指定为「生成前预检项」的环节**（失败半径最大）：`PRD/93:253`（EL-02）要求多画幅安全框
   「在分镜阶段即写入每镜约束，并作为出图/出视频的**生成前预检项**」；`PRD/M4:80`（M4.7-F01）验收是
   「安全区未通过镜头**进入生成**的数量 = 0」。契约做错会被 600 镜/集 × 三画幅继承。
3. **增量真实且为零**：`PRD/90:39-40` 记 M4「29 点 / 已实现 1 / 规划中 28」、M5「31 点 / 已实现 0 / 规划中 30」；
   而 `demo/verify.py` 的 24 项机检**完全不涉及**镜头契约（全文未引用 `MANIFEST['shots']` 的契约字段）。
4. **有现成真样本**：`PRD/96:70-81` 给出先导集 8 镜契约表，`demo/build_demo.py:57-66` 是同一批镜头的代码事实 →
   契约快照可同时对齐「文档表 / 代码 / 复测产物」三处，避免自说自话。
5. **下游直接消费**：`PRD/M6:5` 的上游输入明写「M5 的镜头产物与**摄影参数快照**」（即 M5.2-F05）；
   `PRD/M11:5` 的上游输入明写「**M4/M5 多画幅安全框约束**」；`PRD/M6:59`（M6.3-F07）要求「与 M5.6-F03 摄影漂移**共用报告**」。
6. **顺带把一句声明变成机检结论**：`PRD/96:83` 声称「三画幅逐镜通过率 3 画幅 × 8 镜 = 100%」，
   但 `demo/verify.py:99-112` 只断言容器宽高比、`:141-144` 只按 EBU 5% 断言**字幕**框 —— 画面安全区与逐镜构图**无任何机检**。

## 四、异议方（B · 母版 QC 与声音合规）核心理由

- **对 P1 退出标准的覆盖面更直接**：`PRD/00:192` 的退出标准是「2.39 母版 + 24fps + −23 LUFS 合规 + TC 通过」，
  四项都是**母版成品参数**，量测面落在 M11.3/M11.5 与 M8.5；而 A 自述不覆盖 −23 LUFS 与 TC。
- **TC 在全链路完全不存在**：`demo/out/timeline.json` 无 timecode 字段，`delivery_sheet.json` 与
  `master.metadata.json` 也无 TC；`PRD/96:155` 把「ProRes 母版编码与 TC 嵌入」列为**待接** → 从 0 到 1。
- **并指出 A 的一个真实盲点**：A 所依赖的 NFR-09/NFR-10 在 90 号 NFR 矩阵里被顶替成了别的指标
  （见 [P1-待裁决清单](P1-待裁决清单.md) C-01），A 在附录层的可验收路径本身就是断的。

## 五、全体一致标注的最大风险（写入强制缓解）

> **共同风险**：「契约层自证闭环」——一套断言最终只证明我们自己的纯函数与自己的程序化代理画面自洽，
> 而「真实模型是否按契约出片」完全未被验证；若此时对外称「P1 主干已启动」，就是 **D12 最大风险**
> （代理样片被误读为成片能力，`PRD/93:207`）的重演。

**强制缓解（本切片已全部落地，逐条可机检）**：

| # | 缓解措施 | 落地位置 | 机器验证 |
|---|----------|----------|----------|
| 1 | 变异测试配平：每条规则至少一个违例样本，且「规则注册表 == 变异样本集合」 | `film/fixtures/mutations/`、`RULES` | 复测项「规则注册表 ↔ 变异样本配平」 |
| 2 | 像素真值：安全框只读磁盘代理图的**解码像素**判定，并做像素↔声明包围盒对账 | `tools/verify_p1_a.py` `measure_subject_from_png` | 复测项「像素测量 S0X 与声明包围盒一致」（公差 3px） |
| 3 | **负样本必须失败**：注入参考实现原构图（S03 x=0.58、S07 y=0.66）必须判 FAIL | 复测 A11 段 | 复测项「负样本：参考实现原构图…」 |
| 4 | **锚点互核**：用同一判据量参考实现，必须检出真实缺陷（3 镜不合格） | `film/anchor.py` | 复测项「锚点互核：参考实现 S07 必须被判不合格」+「缺陷清单与产物一致」 |
| 5 | 阈值必须带来源；项目自定值不得冒充官方硬阈值 | `declared_thresholds.json` | 复测项「项目自定阈值均带来源」 |

| 7 | 代理纪律：产物与收据均标 PROXY；门禁收据署名一律占位 | `contract.json`、`gate_receipt.json` | 复测项「代理声明（EL-16）」「门禁收据不冒充人工署名」 |

## 八、本次选举的机制自评（哪里还不足）

1. **选项设计仍有偏向**：题干里我写了每个选项的「机器可验证性」自评，客观上引导了投票方向。
   下一轮应把自评**后置**（先让评估员独立评级，再与我给出的自评对照），或干脆不给自评。
2. **B 的异议依据更硬却只拿 1 票**：B 指出的「P1 退出标准四项都是母版参数」是事实；
   A 胜出靠的是「失败半径 + 增量 + 可验证性」的组合拳，而不是「更贴近退出标准」。
   这说明本轮的判据权重实际落在「可机检性」上——**应在题干里显式声明权重**，否则结论的适用范围会被误读。
3. **未覆盖项靠投票外的方式兜底**：B/C/D 的诉求实际由「登记 + 字段契约 + schema 预留」承接，
   但这部分**没有进入选项排序**，属于主代理的判断。下一轮应把「落选诉求的覆盖方案」也作为可投票项。

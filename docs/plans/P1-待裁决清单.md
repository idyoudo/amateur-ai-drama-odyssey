# P1 待裁决清单（实现过程中实测发现的 PRD 冲突与缺口）

> **本文件不修改 PRD**，只登记。依据：`GOVERNANCE.md` 强规则一（PRD 任何改动须三处登记）与强规则二（L1 独占定义口径）。
> 每条给出：出处（可复核）→ 影响 → 建议处置 → 机器验证方式 → 登记路径（改动 PRD 时的合规姿势）。
> 判定原则：**以 L1（`PRD/00-项目背景.md`）为唯一事实来源**；附录与模块与之冲突时，冲突方按缺陷处理。

## 一、冲突与缺口清单

### C-01 · NFR-09 / NFR-10 编号口径冲突（L1 与 90 号附录）

- **出处**：`PRD/00-项目背景.md:171-172` 定义 **NFR-09 = 画幅与安全框**、**NFR-10 = 帧率与运动质感**；
  `PRD/90-评审与验收清单.md:83-84` 却写 **NFR-09 = 任务成功率 ≥95%**、**NFR-10 = 付费调用可追溯**；
  而 `PRD/90-评审与验收清单.md:105`（M1.1-F05）与 `PRD/M4-分镜previz与导演台.md:81` 又按 L1 口径引用 NFR-09。
- **影响**：P1 退出标准的两项（2.39 画幅、24fps）在 90 号的 NFR→模块追溯矩阵里**没有对应行**，可验收路径断裂；
  违反 GOVERNANCE 稳定 A（NFR 编号与口径由 L1 独占）。
- **建议处置**：按 L1 口径重写 90 号第四章 NFR 矩阵的 NFR-09/NFR-10 两行（附录级修订）。
- **机器验证**：脚本比对 `00-项目背景.md` 与 `90-评审与验收清单.md` 的 NFR 编号→指标映射是否一一对应。
- **登记路径**：`--new-entry --type 修订 --level 附录 --files PRD/90-评审与验收清单.md --refs NFR-09,NFR-10,EL-02,EL-09`。

### C-02 · 景深意图枚举三值 vs 二值

- **出处**：`PRD/M4-分镜previz与导演台.md:36`（M4.2-F03）要求「景深意图（**浅/中/深**）」；
  `PRD/M5-电影摄影与画面生成.md:34`（M5.2-F02）要求「每镜声明 **shallow / deep**」。
- **影响**：同一字段两套合法集合，两侧都要求「完整率 100%」，无法同时满足；映射表无从唯一落定。
- **建议处置**：以 M5 的二值为 canonical（平台只认措辞，三值中的「中」无独立可实现语义），M4 增加别名映射说明。
- **本切片处置**：取二值 canonical，并把「浅/中/深」写成别名（`中 → shallow`），记录在 `film/enums.py`。
- **机器验证**：枚举构造期拒绝集合外值（已完成，含变异样本）。

### C-03 · 色温档封闭集合与先导集演练冲突

- **出处**：`PRD/M5-电影摄影与画面生成.md:47`（M5.3-F05）列出 **2700/3200/4300/5600/6500K 五档**；
  `PRD/96-先导集演练.md:80` 的 S07 声明 **3000K**。
- **影响**：按 M5.3-F05 原样实现，先导集演练的 S07 **自身过不了本模块规则**，演练结论不可执行。
- **建议处置**：二选一——① M5.3-F05 扩档至含 3000K（灯具备 3000K 常见档位，属物理合理）；
  ② 96 号 S07 改为 3200K。**建议 ①**（扩档不改变任何已有约束的强度，且 3000K 是实用光常见值）。
- **本切片处置**：`film/enums.py` 的 `CCT` 取六档（含 3000K），并在代码注释指向本条；
  **不因此掩盖问题**——SC-EP01-02 内 3000K/3200K 并存仍被漂移规则告警（见 C-05）。
- **机器验证**：`R-CCT-CLOSED` + 变异样本 `mut_cct_closed`（3800K 必须被拒）。

### C-04 · 焦距档「六个 mm 值 vs 五个中文档名」

- **出处**：`PRD/M5-电影摄影与画面生成.md:33`（M5.2-F01）给 **18/24/35/50/85/135mm** 六个值，
  却只给**五个**中文档名（超广/广/标准/中长/长焦，135mm 无对应档名）；
  `PRD/M4-分镜previz与导演台.md:36` 给**六个**档名（超广/广角/标准/中长/长焦/超长焦）。
- **影响**：档名与 mm 值无法一一对应，提示词映射表与跨模块引用会漂移。
- **建议处置**：统一按 M4 的六档名，M5.2-F01 补齐「超广角/超长焦」两个档名。
- **本切片处置**：`LENS_LABEL` 采用六档名，代码注释指向本条。
- **机器验证**：`LENS_MM` 与 `LENS_LABEL` 键集必须相等（可在 `--all` 或单测中断言）。

### C-05 · 先导集镜头契约表引发的同场戏漂移告警（契约层待锁）

- **出处**：`PRD/96-先导集演练.md:74-81` 的 8 镜表：SC-EP01-01 内 24/35/85mm 并存；SC-EP01-02 内 35/50/85mm 并存；
  SC-EP01-02 内色温 3000K（S07）与 3200K（S04/S05/S06）并存。
  而 `PRD/M4-分镜previz与导演台.md:36`（M4.2-F03）要求「**同场戏锁定同档**（焦距）并做跨镜漂移告警」，
  `PRD/M5-电影摄影与画面生成.md:47`（M5.3-F05）要求「**同场景默认锁同温**」。
- **影响**：按 M4.2-F03/M5.3-F05 实现，先导集契约表**必然**产出 4 条漂移告警（本切片实测：lens×2、cct×2）。
  这不是实现缺陷，而是**契约表尚未锁定镜头语言/色温**的真实状态。
- **建议处置**：先导集镜头契约表在分镜门禁前显式锁定「同场戏焦距档 + 色温」，或把「同场戏」粒度改为
  「同场戏同一光位组」并在 M4.2-F03 写明例外条件；否则「漂移告警」会长期噪声化（告警疲劳 → 门禁形同虚设）。
- **本切片处置**：**如实告警**（`drift.json` 4 条，全部带镜号与场次），不静默抑制。
- **机器验证**：`R-DRIFT-lens`/`R-DRIFT-clock`/`R-DRIFT-cct` + 变异样本各 1 条必须命中。

### C-06 · P1 退出标准与分期分工不一致（M8/M9 被划入 P2）

- **出处**：`PRD/00-项目背景.md:192` 与 `PRD/90-评审与验收清单.md:599` 的 P1 退出标准含
  「**−23 LUFS 合规 + TC 通过**」；但 `PRD/00-项目背景.md:193` 与 `PRD/90:600` 把 **M8（声音）与 M9（剪辑）划入 P2**，
  P1 主要模块只列 M2/M3/M4/M5/M6/M7/M10/M11/M13/M14。−23 LUFS 的落点 EL-07 在 M8（`PRD/93:258`），
  TC 基线在 M9（`PRD/M9-剪辑节奏与时间线.md:63`）。
- **影响**：P1 要验收「响度与 TC」，却不含承载模块 → P1 与 P2 的边界不可执行；排期与门禁资源无从计算。
- **建议处置**：明确 P1 的响度/TC 由 **M11 母版 QC**（NFR-13 落点 M11.5/M12.1）承担，
  或把 M8/M9 的最小切片纳入 P1；二者选一并在 L1 路线图表中写明。
- **本切片处置**：不动分期，按 `not_verified.json` 显式标注不覆盖。

### C-07 · 96 号附录手抄的 Demo 实测值与 97 号自动生成报告不一致

- **出处**：`PRD/96-先导集演练.md:146,148,149,151` 写 **真峰值 −3.75 dBTP / 动画分镜 400 帧 / 字幕 #2=6.0s / ΔE 1.79**；
  而由 `demo/report.py` 自动生成的 `PRD/97-Demo验证报告.md:21,23,35,39` 与 `demo/out/qc/qc_report.json` 实测为
  **−4.61 dBTP / 288 帧 / #1=#2=5.50s / ΔE 1.61**。
- **影响**：同一份测量在附录间漂移；这正是 `docs/agent-prd-method.md` 记录的「手抄导致数字漂移」反模式。
  对外引用 96 号数字会与可复现产物矛盾。
- **建议处置**：96 号 §8 的表格改为**引用 97 号/`qc_report.json`**（或由 `demo/report.py` 一并生成该表），
  不再手抄；若保留手抄值，必须标注采集时点与产物版本。
- **机器验证**：脚本比对 96 号 §8 表格数值与 `demo/out/qc/qc_report.json` 的 `checks[].value`。

### C-08 · 参考实现（demo）构图不满足多画幅安全框 —— 本轮的决定性发现

- **出处**：`demo/build_demo.py:57-66` 的 `SHOTS`（subject_x / subject_scale）与 `:82-108` 的构图语义；
  判据见 `PRD/00-项目背景.md:171`（NFR-09）与 `PRD/93-决策选举记录.md:39`（D1 缓解措施 1：多画幅安全框前置）。
- **实测（本切片 `anchor_crosscheck.json`，并已由复测脚本独立复算确认）**：
  | 镜 | subject_x / scale | 不合格原因 |
  |----|-------------------|------------|
  | S03 | 0.58 / 0.72 | 头部椭圆在 **9:16 右溢 15px** |
  | S04 | 0.36 / 0.44 | 头部椭圆在 **9:16 左溢 66px** |
  | S07 | 0.62 / 0.88 | 头部椭圆在 **9:16 右溢 128px**；且关键信息区在 **2.39 越出 action safe** |
- **影响**：与 D1 决议自陈的**最大风险**（9:16 衍生版质量塌陷）直接相关。
  注意：**这不动摇 demo 已发布的 24/24 结论**——`demo/verify.py` 的判据集合**不含**多画幅安全框
  （`PRD/96:155` 已自陈「覆盖不到：ProRes/TC/ACES/5.1/口型/EDF 回批/真实缺陷检测」）。
  风险在于**外部引用**：把 demo 当作「多画幅安全框已验证」的样本会过度承诺。
- **建议处置（三选一，需显式决议）**：
  1. **返修参考实现（推荐）**：把 `demo/build_demo.py` 的 S03/S04/S07 构图参数改到本切片求得的可行区间
     （S03 x≤0.560；S04 x≥0.406；S07 x∈[0.440,0.560] 且 y≥0.724），重渲染并跑 `demo/verify.py` 确认仍 24/24；
     **无需改 PRD**（96 号表不含构图几何字段）；
  2. **仅登记**：在 96 号 §8 增补「安全框未验证且实测 3 镜不合格」的缺口条目（G-10），
     并把 demo 的定位收敛为「规范合规**不含**多画幅安全框」；
  3. **收窄判据**：若认为 2.39:1 下关键信息区可被裁切，则须先按同一选举机制复议 D1/EL-02 的缓解措施 1
     ——**不建议**（该措施正是 D1 最大风险的唯一对冲）。
- **本切片处置**：**不擅自返修 demo**（避免污染既有证据链与越权改参考实现），
  以 `anchor_crosscheck.json` + 复测断言「规则必须检出这 3 镜」把缺陷固定为可复核事实。
- **机器验证**：`tools/verify_p1_a.py` 的「锚点互核」三项断言（含独立复算，不复用 anchor 模块产物）。

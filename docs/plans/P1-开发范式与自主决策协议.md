# P1 开发范式与自主决策协议

> 本文固化 P1 实现阶段的**开发范式**与**自主决策协议**，供所有 Agent harness 遵守。
> 依据：`AGENTS.md`（唯一事实来源）+ `docs/architecture.md` + `docs/plans/P1-实施计划.md`。
> 用户不参与决策；争议与拍板项一律走 5 人多智能体选举。

## 一、开发范式（六步流水线，每个模块必须走完）

1. **需求 PRD** —— 唯一需求来源 `PRD/M#.md`（功能点、验收指标、退出标准），不另立需求。
2. **需求理解（任务、功能）** —— 认领 `P1-实施计划` 工单 `W#-#`，锁定功能点 `M#.#-F##` 与验收命令。
3. **设计（接口、数据库等）** —— 落 `docs/designs/`（数据模型/API 契约/任务编排）；有争议走选举，不直接问人。
4. **编码** —— 范围控制在**模块级别**：`film/` 纯函数媒体核心 + `apps/` 薄 API/worker（API 薄、worker 重）。
5. **测试** —— 生成与复测分离、复测器只读磁盘产物；机器门禁（三条必绿命令）+ 变异测试 + 对抗式自评。
6. **部署构建** —— `scripts/deploy-remote.sh`；数据库/目录/数据卷与 retail 三方隔离（见 `docs/guid/remote-deploy.md`）。

## 二、模块级范围纪律

- 每次开发**只动一个模块**：一个 `docs/modules/M#-*.md` 总入口、对应 `film/*` 或 `apps/*` 包。
- 跨模块依赖按 `P1-实施计划` 批次顺序解（第 0 批 M13/M15/M16 → 第 1 批上游 → …）。
- 全部模块实现完成后，进入**联调阶段**，按端到端链路（小说→成片）逐段打通并补集成验收。

## 三、文档不漂移（机器强制）

需求→`PRD/`；设计→`docs/designs/`；计划决策→`docs/plans/`；验证证据→`docs/spec/`；模块台账→`docs/modules/`；部署→`docs/guid/`。
三处台账（强规则一）+ 模块文档登记（强规则三）+ 索引一致 + 断链检查（`prd_guard.py --all`）机器强制，漂移即被拦。禁止把实现细节写回 PRD。

## 四、开源参考政策

- 只参考**顶级优秀、维护活跃**的开源项目；**过时、废弃、无人维护、质量差的一律不参考**。
- 参考前先核：维护状态 / license 是否商用友好 / 是否与本模块技术栈匹配。
- 只借鉴其**模式**（队列/幂等/intent log/fencing 等），不复制代码、不引入平行技术栈。
- 本项目 Python 3.9 单仓；宿主 `retail-trading-odyssey` 与 `audit-worker-platform` 只作模式参考。

## 五、自主决策协议（选举替代人类拍板）

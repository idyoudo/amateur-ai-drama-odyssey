# 团队与角色权限方案

> 目标：把单管理员系统升级为可登录的多成员团队，按角色控制读写，覆盖制片、导演、编剧、剪辑、QC、法务等岗位。

## 一、角色与权限

| 角色 | 标识 | 写入权限 | 说明 |
|------|------|----------|------|
| 管理员 | admin | 全部 | 团队管理、模型配置、全部制作操作 |
| 制片 | producer | 制作类写入 | 项目/分集/审核/分发/结算等 |
| 导演 | director | 制作类写入 | 创作与审核 |
| 编剧 | writer | 制作类写入 | 剧本/分集/项目 |
| 剪辑 | editor | 制作类写入 | 剪辑/交付 |
| QC | qc | 制作类写入 | QC/审核 |
| 法务 | legal | **只读** | 合规查看，不允许写入 |

权限策略（服务端中间件执行，前端只是界面适配）：

- 所有 `/api/*`（登录除外）必须有有效令牌。
- `GET`：所有启用成员可读。
- `POST/PUT/PATCH/DELETE`：法务只读；其余角色可写。
- `/api/team` 写操作、`PUT /api/models/config`：仅管理员。
- 当前登录账户不能停用/降级自己；系统必须保留至少一名启用中的管理员。

## 二、认证

- 首次启动若 `users` 表为空且配置了 `ADMIN_PASSWORD`，自动创建管理员（PBKDF2-SHA256 哈希，120k 次迭代）。
- 登录优先查数据库；旧部署仍可用环境变量管理员凭据登录。
- 令牌仍为 HMAC 签名（24 小时），角色每次请求从数据库读取，角色调整即时生效。
- 密码只存哈希，不落明文、不回传。

## 三、接口

- `GET /api/auth/me`：当前用户名、角色、角色名。
- `GET /api/team`：成员列表 + 角色字典（所有成员可读）。
- `POST /api/team`：添加成员（管理员）。
- `PATCH /api/team/{id}`：修改角色/状态/重置密码（管理员）。
- `DELETE /api/team/{id}`：删除成员（管理员）。

## 四、页面

- 系统 → 团队：成员统计、成员列表、角色/状态。
- 管理员可见「添加成员」与「编辑/删除」；其他角色只读。
- 编辑弹窗支持改角色、启用/停用、重置密码。
- 设置页显示当前登录账户与角色。

## 五、非目标

- SSO / OAuth / 邮件找回密码。
- 项目级细粒度 ACL（当前为全局角色）。
- 操作审计日志（后续可接 `intents`/审计表）。

# Agent 大规模文档与交付物工作法（Amateur AI Drama Odyssey 好莱坞级 PRD 实践总结）

> 适用场景：一次会话内产出**成体系的大型文档 + 可运行交付物**（PRD、规格书、演练与 Demo），要求在无人逐步指导下自决、自证、自纠。
> 本文由 2026-10 的「Amateur AI Drama Odyssey（`amateur-ai-drama-odyssey`）好莱坞级 PRD + 先导集演练 + 规范 Demo」实践提炼：最终产出 31 个 PRD 文件 / 4992 行 / 631 功能点 / 273 条可核验依据 + 1 个可运行 Demo（独立复测 24/24 通过），全程零提问。

## 一、八步工作流（可复制）

| 步 | 动作 | 判据（做到才算完成） |
|----|------|----------------------|
| 1 | **先立规则，再写内容** | 规则文件先于内容文件落地：分层、编号、字段、状态取值、依据写法、命名与退役规则 |
| 2 | **建编号化依据库** | 每条结论有可定位编号（对标/标准/开源/论文/工程/成本），且标注取证等级 |
| 3 | **争议走选举，不走请示** | 有争议 → 结构化选项 + N 名独立评估员 + 多数决；平票加选 |
| 4 | **并行扇出，单一写者** | 每个子代理只写自己那份文件；主代理只做跨文件一致性与退役旧件 |
| 5 | **把可判定的写成机器判定** | 状态合法性、证据完整、编号唯一、依据可解析、链接可达 → 脚本化、fail-closed |
| 6 | **对抗式自评循环** | 每轮问「这份东西会被怎么执行错/怎么钻空子」，缺陷必须闭环或明确登记 |
| 7 | **交付物必须能被第三方复测** | 复测只读产物、不复用生成器内存；报告由实测数据生成，禁止手抄 |
| 8 | **不冒充、不承诺未验证** | 代理样片标 PROXY；未取到原文的数值标「待补原文」且不得作为验收阈值 |

## 二、关键机制（本次真正起作用的部分）

1. **选举的胜负判据要写进提问里**：要求每位评估员给出「胜出理由 + 最大风险 + 强制缓解措施 + **落选方案的核心诉求如何被低成本覆盖**」。
   - 这条要求直接产出了高质量设计：9:16 衍生层、22 分钟备剪版、第二季期权、季终集上探 45 分钟——而不是简单二选一。
2. **决策必须回填到执行层**：决议（D1–D14）→ 派生硬性要求（EL-01~EL-16）→ 落到具体模块的功能点依据行。
   - 本次自评抓出「第二轮决议未落到任何模块」的可追溯性缺口并回填 19 个模块，这类缺口只有机器检查才能兜住。
3. **复测与生成分离**：生成器写产物，`verify.py` 只读产物重新测量（响度、位深、时基、画幅、字幕规则、标识、色差），任一失败即 QC FAIL 并阻断。
   - 复测必须**晚于**被检对象产生（本次就因为顺序错误导致 0 分判定），并校验「文件存在且非空」。
4. **实测数据驱动文档**：`report.py` 依据 `qc_report.json` 生成 PRD 附录与 README，避免文档数字与产物流水线漂移。
5. **阈值诚实**：行业无统一标准的值（ΔE、闪白 PSE、安全区百分比）明确标为「项目自定」，并写进 QC 报告与门禁条件。

## 三、本次真实踩过的坑（建议固化为检查项）

| 类别 | 现象 | 正确做法 |
|------|------|----------|
| 并发 | 多个子代理同改一个目录，存在互相覆盖风险 | 子代理只许写自己那份文件；主代理删除旧件前先确认替代件非空 |
| 工具缺失 | 本机无 ffmpeg、无 GPU、无付费凭据 | 把约束当设计输入，选「可自证的最小产物」：numpy/Pillow 生成代理画面、自实现 ITU-R BS.1770 复测响度 |
| 库行为假设 | 以为 WebP 存 304 帧就是 304 帧；实则**有损编码会量化合并极暗帧**，代理时长少了 0.49 s | 不假设，实测；代理样片只含内容帧，黑场按时间线资产验证；时基判定用「时长守恒」而非帧数硬比 |
| 自证假通过 | 色卡 ΔE 从自身渲染取样 → 恒为 0.0，无检验价值 | 从**有损编码后**的产物取样（区域中位数）对比声明参考，首次实测即 FAIL(7.0)，修因后 1.79 通过 |
| 声明不符 | 元数据写 24-bit，实际 16-bit WAV | 复测从文件头读位深/声道/采样率并断言 |
| 长时间任务 | 前台超时被转后台、外层 shell 退出会杀掉 `&` 起的进程 | 用受管后台任务；为迭代加 `--reuse` 路径，把分钟级重建压到秒级 |
| 派发信息不足 | 子代理虚引不存在的依据编号（如 ObjectAlign） | 派发时给「必读清单 + 依据编号范围 + 禁止修改文件清单」；宁可让它标注缺口，也不许编造 |

## 四、角色分工（人类只做不能自动化的部分）

| 环节 | Agent | 人类 |
|------|-------|------|
| 调研与对标 | 检索、抓原文、分级取证、登记编号 | — |
| 方案争议 | 生成选项、组织选举、记录票型与缓解措施 | 事后复核决议 |
| 撰写与一致性 | 并行撰写、跨文件审计、编号与链接校验 | — |
| 质量与合规 | 机检门禁、独立复测、缺口登记 | 五门禁署名与终审（AI 异议不得静默覆盖） |
| 信任边界 | 标 PROXY、标「待补原文」、暴露 FAIL | 决定是否对外承诺与发布 |

## 五、验收清单（可直接复用）

- [ ] 规则文件先于内容文件存在，且被内容引用
- [ ] 每个结论有编号依据；无同号异义；无悬空引用
- [ ] 每条功能点有现状证据（`file:line`）或明确写「无」
- [ ] 争议项有选举记录（票型、异议、风险、缓解、落选诉求覆盖）
- [ ] 决议已派生硬性要求，且硬性要求能在模块中被检索到
- [ ] 机器判定脚本 fail-closed，且晚于被检对象生成
- [ ] 交付物可被第三方按 README 一键复现，复测结论与文档数字一致
- [ ] 代理/模拟产物显式声明，未验证项显式标注，失败项进入缺口表
